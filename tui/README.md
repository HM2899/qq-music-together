# QQ音乐 TUI

把 `qq-music-together/` 那个网页版（`index.html` + `app.js` + `style.css`）改成终端界面。
原网页保留不动，这是并行的 Go 实现。

功能上与桌面版 Quickshell 客户端（`~/.config/quickshell/statindet/Modules/QQMusic/`）对齐：
七个页签，复用桌面版后端接口与队列语义。真实后端已随仓库和安装包提供，无需安装 Quickshell；环境准备与 Linux 软件包安装见[项目说明](../README.md)。

## 跑起来

```bash
cd tui
make run          # 等价于 go build -buildvcs=false -o qqmusic-tui . && ./qqmusic-tui
```

依赖：`mpv`（播放引擎）、`python3`（后端接口脚本）。
后端仅需 Python 标准库和系统 CA。脚本按序找：

1. 显式 `$QQMUSIC_API`（无效则报错，不继续回退）。
2. 可执行文件相对路径 `../share/qqmusic-tui/backend/qqmusic_api.py`（系统包、便携包）。
3. 可执行文件旁 `backend/qqmusic_api.py`（源码构建）。
4. `/usr/local/share/qqmusic-tui/backend/qqmusic_api.py`、`/usr/share/qqmusic-tui/backend/qqmusic_api.py`。

不从当前工作目录选择脚本，也不自动运行外部 Quickshell 配置里的代码。后端会话仍保留历史路径 `${XDG_CACHE_HOME:-$HOME/.cache}/quickshell/qqmusic/`；与旧桌面客户端共享该目录时，登录/退出会互相影响，不会自动迁移旧数据。

`./qqmusic-tui --version` 和 `--help` 不启动播放器、数据库或网络。找不到脚本时会明确报错，不会静默降级。想不出声地跑：

```bash
QQMUSIC_TUI_NO_AUDIO=1 ./qqmusic-tui
```

## 播放栏

进度条下面显示三句滚动歌词（上一句 / 当前句带翻译 / 下一句），终端矮于 30 行时只显示当前句，低于 20 行不显示；
「正在播放」页本身就是整屏歌词，底下不重复。右侧显示正在播放的这首**实际拿到的**音质——
所选档位这首歌没有时会自动降一档（比如没有无损就用 320k），状态栏会说明。
Hi-Res（RS01）实测给地址但下载 404、臻品母带拿不到地址，所以不提供这两档。

## 记住上次的播放（SQLite）

队列、当前第几首、播到哪、音量、静音、音质存在 `~/.local/share/qqmusic-tui/state.db`（`QQMUSIC_TUI_DB` 可覆盖）。
下次启动原样恢复，**暂停**在上次的位置；按 `空格`（或灵动岛 / 媒体键的播放）从那里接着放，切歌则正常从头开始。
切歌、改队列、调音量、换音质时立刻写盘；只有位置在变时每 5 秒写一次；退出时再强制写一次。
旧版本存在 `~/.config/qqmusic-tui/config.json` 的音质设置会在第一次存盘时迁进数据库。
SQLite 用的是纯 Go 的 `modernc.org/sqlite`，不需要 cgo。

## 专辑封面

「正在播放」页左边显示专辑封面：用半块字符 `▀` + 24 位真彩色画（每格两个像素，正好方形），
所以需要支持真彩色的终端（kitty / foot / wezterm 等都行）。窄于 70 列时不显示，整页给歌词。
没用 kitty 图形协议：bubbletea 的差分渲染会把图片转义序列切坏。封面下载失败就不显示，也不反复重试。

## 七个页签

| # | 页 | 数据来源 |
|---|---|---|
| 1 | 探索 | `discover`（每日 30 首 + 推荐歌单） |
| 2 | 搜索 | `search`，可切 歌曲 / 歌手 / 专辑 / 歌单，支持翻页，一页 30 条 |
| 3 | 正在播放 | 本地状态 + `lyrics`（含翻译），歌词随播放位置滚动 |
| 4 | 我喜欢 | `favorites` |
| 5 | 音乐库 | `library`，选中歌单回车进入详情 |
| 6 | 播放队列 | 本地队列，可移除单曲 / 清空 |
| 7 | 我的歌单 | `library` 里自己创建 / 收藏的歌单；`N` 新建、`D` 删除（需按 y 确认，「我喜欢」不能删） |

歌单和专辑是**盖在当前页上的一层**：从哪一页进去就在哪一页显示，`esc` 退回原来那份列表，
所以搜索结果、探索页推荐位、音乐库里都能直接展开，`]` 继续翻这个歌单的下一页。

按 `c` 打开**评论浮层**（当前在播的那首）：`j`/`k` 滚动、`]`/`[` 翻页、`s` 切换 热评 / 最新、`l` 点赞 / 取消、`w` 写评论（回车发送、`esc` 取消，草稿保留）、`esc` 关闭。评论正文自动换行完整显示。「最新」只能按游标翻页，往回翻会复用当初那一页的游标。

## 快捷键

| 键 | 作用 |
|---|---|
| `1`–`7` / `Tab` / `Shift+Tab` | 切换页签 |
| `/` | 搜索（直接进入输入框） |
| `Ctrl+T` | 搜索页：切换 歌曲 / 歌手 / 专辑 / 歌单 |
| `]` `[` / `Ctrl+F` `Ctrl+B` | 搜索页：下一页 / 上一页；详情页：`]` 或 `Ctrl+F` 加载更多；输入框里用 Ctrl 组合键 |
| `↑` `↓` / `j` `k` | 移动选择 |
| `g` / `G` | 跳到首 / 尾 |
| `回车` | 曲目 = 播放（**整段替换**队列）；歌单/专辑 = 进详情；歌手 = 按名字搜他的歌 |
| `a` | 把选中的歌追加到队列 |
| `A` | 把选中的歌（正在播放页是当前这首）加入自己的歌单；浮层里 `N` 可先新建 |
| `Q` | 切换音质：标准（m4a）→ 128k → 320k → 无损（FLAC），保存在 SQLite 状态库；正在放的歌从当前位置换成新音质接着放 |
| `f` | 收藏 / 取消收藏（正在播放页作用于正在听的那首；方向以服务端实时状态为准，需登录） |
| `空格` | 播放 / 暂停 |
| `n` / `p` | 下一首 / 上一首 |
| `←` / `→` | 快退 / 快进 5 秒 |
| `-` / `=` | 音量 ±5% |
| `m` | 静音开关 |
| `L` | 未登录：扫码登录；已登录：账号页（换号 / 退出登录） |
| `r` | 刷新当前页 |
| `c` | 看当前曲目的评论（队列页的 `c` 是清空队列） |
| `d` | 队列页：移除选中；自己歌单的详情里：把选中的歌移出这个歌单 |
| `?` | 快捷键帮助 |
| `q` / `Ctrl+C` | 退出 |

搜索框是 **fzf 语义**：除了 `回车`（搜索）、`esc`（退出输入）、`↑↓`/`PgUp`/`PgDn`（直接移动
结果列表）、`Ctrl+T`/`Ctrl+F`/`Ctrl+B` 之外，所有键都进输入框。所以在框里按 `q` 打出的是
字母 `q`，不会退出程序；想播放结果要先按 `esc` 离开输入态，再按 `回车`——
`]` 在输入框里只是个中括号字符，翻页要用 `Ctrl+F`。

歌手那一类的 `回车` 是「按歌手名搜他的歌」而不是进歌手页：歌手的曲目列表接口
`music.web_singer_info/GetSingerSongList` 实测只回 `500003/860100005`（这个签名问题和
写接口无关——写接口不带签名也能通，见「明确不做」），目前只知道 `music.musichallSinger.SingerList`
这一个歌手接口，拿不到曲目列表，所以退化成按名字搜。

登录层（按 `L`）：`r` 重新生成二维码、`t` 切换 QQ / 微信、`o` 用系统看图器打开图片、`esc` 关闭。
扫码成功后登录层自动关闭。已登录时按 `L` 是账号页：`s` 扫码换号、`x` 退出登录、`esc` 关闭。

收藏的 ♥ 按「我喜欢」的全量 songMid 判断（启动和登录后各拉一次，不依赖是否打开过「我喜欢」页）。
按 `f` 时先用 `favorite-check`（`IsSongFanByMid`，实时准确）问一次服务端再决定加还是删——
「我喜欢」列表接口有 CDN 缓存，在桌面客户端或手机上刚改过的收藏它几分钟内还是旧的。

## 队列语义

与桌面版 `playTrack(track, sourceQueue, index)` 一致：从列表里选中一首回车播放会
**整段替换**队列，而不是把之前攒的队列接在后面；替换时会过滤掉明确不可播放的曲目
（VIP / 无版权），避免队列里全是点不动的歌。

## 结构

| 文件 | 职责 |
|---|---|
| `main.go` | 入口，启动 mpv 与 bubbletea 程序 |
| `types.go` | `Track` / `Playlist` / 各接口响应体 |
| `api.go` | 调后端脚本的客户端、错误分类、超时 |
| `commands.go` | 全部 `tea.Cmd` 生产者（异步层与过期响应丢弃） |
| `queue.go` | 播放队列：替换 / 追加 / 增删 / 清空 |
| `ui.go` | `Model`、`Init`/`Update`、按键分派、根布局 |
| `rows.go` | 每页的「行」抽象与游标吸附 |
| `view.go` / `view_pages.go` | 样式 token、通用渲染、七个页面 |
| `input.go` | 手写单行输入框（CJK 光标按显示宽度算） |
| `login.go` / `qr.go` | 扫码登录状态机 + PNG → 半块字符二维码 |
| `mpv.go` | mpv 播放引擎，走 JSON IPC（unix socket） |
| `publish.go` | 把当前播放状态写给桌面 shell 的顶栏歌词 |
| `fixtures_test.go` | 测试用的假曲目与假探索页（`songs.go` 已删，产品里没有内置曲目了） |

播放和进度是**真实**的（mpv 的 `time-pos` / `duration`），歌词按真实播放位置滚动。
直链有时效，每次播放都会重新 `resolve`，不做缓存。

两条并发规则（都是踩过坑才定下的）：

- **网络调用一律走 `tea.Cmd`**，否则脚本 8–38s 的超时会冻住界面。
- **mpv 调用一律留在 `Update` goroutine 里同步发**。`tea.Cmd` 跑在并发 goroutine 池里，
  连按回车时两个 `loadfile` 的到达顺序不确定，出声的会变成随机那首。

## 桌面顶栏歌词

播放状态每 200ms 写到 `~/.cache/qqmusic-tui/now.json`（先写临时文件再 `rename`，
读端不会读到写了一半的内容），桌面 shell 的顶栏歌词胶囊读它。
配好之后不用切到终端就能看到当前歌词，TUI 退出这条就消失。

想写到别处（测试 / 不打扰）：

```bash
QQMUSIC_TUI_STATE_FILE=/tmp/now.json ./qqmusic-tui
```

被 `kill -9` 时来不及删文件，桌面侧靠 `updatedAt` 判断写入是否还在继续，
超过 3 秒没更新就把顶栏那条收掉，所以不会留下僵尸歌词。

## 灵动岛 / 锁屏 / 媒体键（MPRIS）

TUI 在会话总线上注册为 `org.mpris.MediaPlayer2.qqmusic_tui`（`mpris.go`），
所以桌面的灵动岛、锁屏媒体卡、全局媒体键、`playerctl` 都能看到并控制它：
播放/暂停、上一首/下一首、拖进度、调音量。同时开两个 TUI 时第二个用带 PID 的实例名。

外部的控制请求不会在 D-Bus 的 goroutine 里直接动 mpv，而是包成 `mprisMsg` 经
`Program.Send` 回到 `Update` 执行，与「mpv 调用只在 Update 里」的规则一致。

没有图形会话（ssh 里跑）时会自动跳过；想主动关掉：

```bash
QQMUSIC_TUI_NO_MPRIS=1 ./qqmusic-tui
```

`mpris_test.go` 自己起一个私有 `dbus-daemon` 测，不会出现在真实的灵动岛里。

## 明确不做

| 不做 | 原因 |
|---|---|
| 写 `play-history.json` / `playback-state.json` | 刻意不碰后端的共享状态文件（`session.json` 除外，那是登录机制本身） |
| 随机播放 / 单曲循环模式切换 | 当前上下首按队列顺序切换，到边界绕回，未提供模式切换 |
| 网页房间与聊天同步 | 网页与 TUI 是独立实现，目前不互联 |
| 注册进 `MediaManager` | 避免在未播放时接管桌面媒体控制；通过独立 MPRIS 服务提供控制 |

评论发送、点赞、歌单写操作和音质选择已在 TUI 接入；是否成功取决于兼容后端、账号权限与服务端响应。真实 API 脚本不在本仓库内，接口签名和 `songType` 等细节以所用后端实现及歌曲数据为准，不应把某次调试结论当成固定协议规则。

## 测试

```bash
make test        # 全部（不联网）
make test-race   # 带竞态检测
```

测试用一个假后端（`testdata/fake_api.py`，靠 `QQMUSIC_API` 指过去），所以整套
`go test` 不碰网络；mpv 以 `--ao=null` 无头运行，音频由 ffmpeg 现场生成。
覆盖：接口错误矩阵（业务错误 / 网络错误 / argparse / 超时 / 过期响应丢弃）、
页面状态机、焦点语义（搜索框内 `q` 不退出）、搜索类型切换与翻页、歌手回退成按名搜索、
专辑详情下钻与 `esc` 回退、评论浮层与翻页、队列编辑、二维码解码与渲染、
登录层各状态、端到端渲染与按键。

### 需要人工验收的部分

自动化测不到「真的出声」和「真能扫」，这几条要手动过一遍：

1. `make run`，搜索 → `esc` → `回车`：**要真的出声**，进度条前进。
2. 「正在播放」页歌词随进度滚动、切歌不串词（`n`/`p` 走队列）。
3. 按 `L` 用手机真扫一次码，确认终端里画出的二维码能被识别、登录后昵称出现在顶栏。
4. **桌面顶栏胶囊不能被弄坏**：TUI 放真歌时 `~/.cache/qqmusic-tui/now.json` 的
   `track.title` 应是真实曲名，截图确认胶囊照常显示；TUI 退出后胶囊消失。
